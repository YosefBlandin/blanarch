## Overview
<!-- 3 to 6 lines: the shape of the change and the data flow. Add a small diagram only if it saves words. -->
A root npm workspace (D-6) adds two TypeScript packages next to the Flutter app: `packages/contract` (zod schemas shared by server and, later, the admin app) and `server` (Fastify). Docker Compose runs Postgres 17 for local work (D-10). Plain SQL migrations run through node-pg-migrate (D-15); Kysely types the queries (D-8). Tests start a throwaway Postgres through Testcontainers. Tracked git hooks, installed into the shared hooks folder, guard every worktree on any branch (D-12, D-22). One GitHub Actions workflow runs a Linux server job and a macOS app job (D-11).

```
developer ──npm ci──▶ root workspace ─┬─ packages/contract (zod) ◀── imports ── server (Fastify)
                                      └─ server ──pg pool──▶ Postgres 17 (compose, or Testcontainers in tests)
git commit ──▶ <common dir>/hooks/{pre-commit,commit-msg} (copied from .githooks/) ──reads──▶ <main checkout>/private/company-strings.txt
pull request ──▶ CI: server job (ubuntu) + app job (macOS)
```

### Root workspace (AC-1, AC-2, AC-8; D-6, D-14, D-16)
- app:package.json (new): private root, `workspaces: ["packages/*", "server"]`, `engines.node: ">=24"`, scripts `lint`, `typecheck`, `test`, `format`, `format:check`, `prepare` (installs the hooks, see below). app:package-lock.json (new) is committed.
- app:.nvmrc (new) holds `24`. app:tsconfig.base.json (new): strict, `module`/`moduleResolution` `nodenext`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `allowImportingTsExtensions`, `noEmit`.
- app:eslint.config.js (new): ESLint flat config with typescript-eslint type-checked rules and eslint-config-prettier. app:.prettierrc.json (new) and app:.prettierignore (new); Prettier and ESLint cover only the workspace folders, never blanarch/ or docs/.
- app:.gitignore gains node_modules/, dist/, coverage/ and *.tsbuildinfo.
- The Flutter and Gradle trees are untouched; their tools never walk up to the root (Facts).

### Contract package (AC-5; D-6)
- app:packages/contract/package.json (new): name `@blanarch/contract`, `type: module`, `exports` pointing at `./src/index.ts`.
- app:packages/contract/src/health.ts#HealthResponse (new): the zod schema of the health reply (Contracts). app:packages/contract/src/index.ts (new) re-exports it.

### Server (AC-4, AC-5; D-14, D-17, D-18)
- app:server/src/config.ts#loadConfig (new): parses `process.env` with a zod schema (Contracts, Settings). On failure it prints one line per bad setting, name and reason only, and exits 1 before anything listens.
- app:server/src/db.ts#createDb (new): one `pg` Pool and a `Kysely<Database>` on it. It attaches a `pool.on('error')` listener that logs without the connection string, so a database restart never crashes the process, and sets `connectionTimeoutMillis` so no checkout waits forever. The health time limit itself lives in the route (Contracts, Health check). app:server/src/db/types.ts#Database (new) is generated by kysely-codegen from a migrated database and never hand-edited.
- app:server/src/app.ts#buildApp (new): builds Fastify with the zod type provider, pino logging with redaction, and the routes. Takes config and db as arguments, so tests build it without listening.
- app:server/src/routes/health.ts#healthRoutes (new): `GET /healthz` (Contracts).
- app:server/src/server.ts#main (new): loads config, builds the app, listens, and handles shutdown (States and exits).
- app:server/.env.example (new): every setting with a local placeholder value. The real `server/.env` stays ignored.

### Migrations (AC-6; D-8, D-15)
- app:server/migrations/ (new): node-pg-migrate SQL files, `<timestamp>_<name>.sql`, each with `-- Up Migration` and `-- Down Migration` sections. The first one enables the citext extension that phase 1 needs.
- Scripts in app:server/package.json (new): `migrate` (apply all pending), `migrate:create`, `db:types` (regenerate app:server/src/db/types.ts#Database).
- Migrations run as a separate command, never on server start.

### Local database (AC-3; D-10, D-13)
- app:compose.yaml (new): one `postgres` service on `postgres:17.11`, a named volume, a `pg_isready` healthcheck, port bound to 127.0.0.1 only, user and password from the root ignored `.env`. app:.env.example (new) holds local placeholders.

### Tests (AC-7, AC-8; D-10)
- app:server/vitest.config.ts (new) with app:server/test/global-setup.ts (new): starts one PostgreSqlContainer on `postgres:17.11` per test run, applies the migrations, passes the connection string to tests, stops the container at the end.
- Tests that need isolation create their own uniquely named database. HTTP tests use `app.inject()`; no port is opened.

### Forbidden word hooks (AC-10; D-12, D-22)
- app:.githooks/pre-commit (new) and app:.githooks/commit-msg (new), committed with mode 100755. pre-commit keeps today's scan (every added staged line, case-insensitive fixed strings, `#` comments and blank lines skipped); commit-msg runs the same scan on the message file. Shared logic lives in app:.githooks/forbidden-scan.sh (new).
- The list path is `<git common dir>/../private/company-strings.txt`, so every worktree reads the main checkout's list.
- app:scripts/install-hooks.mjs (new), run by the root `prepare` script, copies the three files into `$(git rev-parse --git-common-dir)/hooks/` and marks them executable. It never sets `core.hooksPath`; if `core.hooksPath` is set it fails with a message. Every worktree shares that folder, so the check runs on any branch, including branches without `.githooks/`, and survives a revert. It replaces today's local hook with the tracked version of the same scan.
- Outside a git checkout (for example an unpacked tarball) the installer does nothing.

### CI (AC-9; D-11, D-20)
- app:.github/workflows/ci.yml (new), triggers: pull requests into qa, staging and main, plus manual runs. `permissions: contents: read`; a concurrency group cancels older runs of the same branch.
- Job `server` on ubuntu-latest: setup-node from `.nvmrc` with npm cache, `npm ci`, `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test` (Testcontainers uses the runner's Docker).
- Job `app` on macos-latest: setup-java Temurin 17, Flutter 3.47.5 stable, `flutter pub get`, `flutter analyze`, `flutter test`; then the Gradle step writes `android/local.properties` from the Flutter root, caps the daemon heap in `~/.gradle/gradle.properties`, validates the wrapper and runs `./gradlew ktlintCheck testDebugUnitTest`. On a golden failure it uploads `test/failures/` as an artifact.
- Actions: first-party actions pinned by major version, third-party actions pinned by commit SHA.
- app:blanarch/android/.gitignore stops ignoring `gradlew`, `gradlew.bat` and the wrapper jar, and those files are committed (D-20).

### Docs and profile (AC-11)
- app:CLAUDE.md: a new Commands block for the workspace (run from the repo root), the new folders in the intro list, and the Docker and Testcontainers gotcha.
- app:README.md: Layout gains server/, packages/contract/ and the compose file.
- app:docs/specs/spec-profile.md (new; untracked at the pin, committed by this PR with this spec folder): `verify.app` adds the workspace checks, preflight adds node 24 and a running Docker, the stale "no remote" note is replaced, and `test.app.server` is added.

## Contracts

### Settings (server environment)
| Name | Type and rule | Default | Secret |
|---|---|---|---|
| NODE_ENV | development, test or production | development | no |
| HOST | host to bind | 127.0.0.1 | no |
| PORT | integer 1 to 65535 | 3000 | no |
| DATABASE_URL | postgres URL | none, required | yes (holds the password) |
| LOG_LEVEL | fatal, error, warn, info, debug or trace | info | no |
- Loaded from the process environment. `dev`, `migrate` and `db:types` all add `server/.env` through Node's `--env-file-if-exists` (or the tool's own env-file option), so they share one DATABASE_URL. Tests get theirs from the test container instead.

### Local compose settings (root `.env`)
| Name | Example placeholder |
|---|---|
| POSTGRES_USER | blanarch |
| POSTGRES_PASSWORD | a local placeholder; compose fails loudly when it is unset (`${POSTGRES_PASSWORD:?}`) |
| POSTGRES_DB | blanarch |
| POSTGRES_PORT | 5432 (bound to 127.0.0.1) |
- app:server/.env.example's DATABASE_URL is built from exactly these placeholders, so copying both example files gives a working setup.
- Postgres keeps the password from the volume's first start. After changing it, reset with `docker compose down -v` (CLAUDE.md Gotchas).
- Invalid config prints `config: <NAME> <reason>` per issue to stderr and exits 1. Values are never printed.

### Health check
`GET /healthz`, unversioned (an operations endpoint, not part of /v1).
- Time limit: 1000 ms in total for getting a pooled connection plus `select 1`, enforced by one per-request timer in the route that releases the client when it fires. Tests assert the status and an elapsed time under 1500 ms (the 500 ms is test slack, not part of the contract).
- 200 with `{ "status": "ok", "db": "up" }` when the probe finishes within the limit.
- 503 with `{ "status": "unhealthy", "db": "down" }` otherwise. No error text, host or driver message in the body; the reason goes to the log without the connection string.
- Schema: app:packages/contract/src/health.ts#HealthResponse.

### Commands (root unless noted)
| Command | Does |
|---|---|
| `npm ci` | installs every workspace and installs the hooks |
| `docker compose up -d` | starts local Postgres |
| `npm -w server run migrate` | applies pending migrations to DATABASE_URL |
| `npm -w server run migrate:create -- <name>` | adds a new SQL migration file |
| `npm -w server run db:types` | regenerates the Kysely types from the migrated local database |
| `npm -w server run dev` | runs the server with reload and server/.env |
| `npm run lint` · `typecheck` · `test` · `format:check` | each runs across every workspace and fails on any error |

### Migration bookkeeping
node-pg-migrate's own table records each applied file by name and time. All pending files run in one transaction under an advisory lock, so a failure applies none of them.

### Hook behaviour
| Situation | Result |
|---|---|
| list found, no hit | commit proceeds |
| list found, n hits | blocked; prints the count and the command to find them, never the strings |
| list missing or empty | blocked; prints the expected path and the opt-out variable |
| list missing or empty and `SKIP_FORBIDDEN_CHECK=1` | proceeds with a warning on stderr |
| list found and `SKIP_FORBIDDEN_CHECK=1` | ignored: scans and blocks on hits as usual |
| commit message contains a listed string | blocked by commit-msg with the same message rules |

### CI checks
Two checks, named `server` and `app`. Branch protection itself is set by the owner. If golden screenshots differ only in rendering on the runner, the app job skips app:blanarch/test/screens_golden_test.dart by path (D-24).

## States and exits
<!-- For anything with a lifecycle (jobs, sessions, retries, rollout windows): each state, how it starts, how it ends, and what happens on failure or timeout. The pre-mortem lens reviews this table. -->
| State | Entered when | Exits when | On failure or timeout |
|---|---|---|---|
| server starting | `main` runs | config valid and listening | invalid config: exit 1 before listening (AC-4); port in use: exit 1 |
| server running, db down | database stops or drops connections after start | database answers | health returns 503 within the health time limit (Contracts); pool errors are logged; the server keeps running and does not exit |
| server stopping | SIGTERM or SIGINT | in-flight requests done, pool closed, exit 0 | after 10 s force exit 1 |
| migrating | `migrate` starts and takes the lock | all pending applied, exit 0 | any SQL error rolls back the whole batch, releases the lock, exit 1; lock already held by another run: exit 1, nothing applied; database unreachable: exit 1 after the connect timeout |
| test database | vitest global setup starts the container | tests finish and teardown stops it | start timeout 60 s fails the run; Testcontainers' cleanup container removes leftovers if the run crashes |
| CI run | pull request opened or updated | both jobs finish | a newer push cancels the older run |

## Cross-cutting
<!-- One short paragraph, or "none", for each: security and permissions; personal data and logs; performance and cost; deploy and infrastructure; observability; old clients. M tier: release order and rollback go here, because M has no release.md. -->
- **Security and permissions:** no endpoints beyond the health check. Postgres binds to 127.0.0.1 only. CI has read-only repo permissions and no secrets.
- **Personal data and logs:** none stored. pino redacts `authorization` and `cookie` headers from day one; config errors and health failures never print DATABASE_URL or other values.
- **Secrets:** root `.env` and `server/.env` are ignored (Facts); only the `.env.example` files with placeholders are committed.
- **Performance and cost:** CI uses free runners on the public repo. The app job takes macOS minutes, which are free here.
- **Deploy and infrastructure:** none (D-13). Release order: one PR into qa; rollback is a revert, since nothing is deployed. The installed hooks stay in the shared hooks folder after a revert and keep scanning (D-22). A revert also deletes the committed Gradle wrapper files from the working tree; restore them by checking them out from the reverted commit or by running a Flutter build. After a revert, node_modules shows as untracked until it is deleted.
- **Public pushes:** the executor installs the hooks before its first commit and runs the pre-push privacy scan in D-25, since CI never sees the private list.
- **Setup in a fresh clone:** the hooks exist only after `npm ci` at the root; README and CLAUDE.md say to run it first.
- **Observability:** structured JSON logs from pino; the health check is the only signal.
- **Old clients:** none; the app does not call the server yet (D-2).
